### Cancellation rate

```python
canceled_orders_rate = (
    len(orders[orders['order_status'] == 'canceled']) / len(orders)
) * 100
```

Formula:

**Cancellation Rate = (Cancelled Orders / Total Orders) × 100**

This tells us what percentage of all orders were cancelled.

### Non-delivered orders

Your code:

```python
non_delivered_orders_rate = (
    len(orders[orders['order_status'] != 'delivered'])
    - len(orders[orders['order_status'] == 'canceled'])
)
```

There is an important naming and calculation issue here.

This calculation gives the **number of non-delivered orders excluding cancelled orders**. It does not calculate a rate yet.

You later divide by total orders and multiply by 100, which correctly calculates the percentage.

A clearer version is:

```python
non_delivered_orders = len(
    orders[orders['order_status'].isin(
        ['shipped', 'unavailable', 'invoiced', 'processing', 'created', 'approved']
    )]
)

non_delivered_orders_rate = non_delivered_orders / len(orders) * 100
```

This specifically counts orders in the listed statuses.

**Remember:** Non-delivered orders and cancelled orders are different categories.

# 2. Delivery Performance Analysis

## Objective

Find out whether Olist delivered orders before, on or after the estimated delivery date.

### A. Convert date columns

```python
orders['order_purchase_timestamp'] = pd.to_datetime(
    orders['order_purchase_timestamp'],
    format='%Y-%m-%d %H:%M:%S'
)
```

You use `pd.to_datetime()` to convert text into a proper date/time format.

Why?

Because Python cannot reliably perform date calculations on ordinary text.

You also convert:

- `order_estimated_delivery_date`
- `order_delivered_customer_date`

**Important improvement:** You convert the last two columns twice. You only need one conversion for each column. Use `errors="coerce"` if invalid dates should become missing values (`NaT`).

### B. Calculate delivery delay

```python
delivery_delay = (
    orders["order_delivered_customer_date"]
    - orders["order_estimated_delivery_date"]
)

orders["delivery_delay_days"] = delivery_delay.dt.days
```

This is an important calculation.

**Formula:**

Delivery Delay = Actual Delivery Date − Estimated Delivery Date

| Result | Meaning |
|---|---|
| Positive number | Delivered late |
| Zero | Delivered on estimated date |
| Negative number | Delivered early |
| NaN | Delivery date is missing |

`.dt.days` extracts the number of days from the date difference.

Example:

Estimated date: 10 November  
Actual date: 13 November  
Delay: 3 days.

### C. Categorise deliveries

```python
late_deliveries = orders[orders['delivery_delay_days'] > 0]
```

Selects deliveries that were late.

```python
ontime_deliveries = orders[orders['delivery_delay_days'] <= 0]
```

Selects deliveries that were early or on time.

```python
valid_delivery = orders[orders['delivery_delay_days'].notnull()]
```

Selects records where delivery delay is available.

`notnull()` identifies values that are not missing.

**Why is this important?**

Orders without an actual delivery date cannot be classified as early, on time or late.

### D. Late delivery rate

```python
late_delivery_rate = len(late_deliveries) / len(valid_delivery) * 100
```

Formula:

**Late Delivery Rate = (Late Deliveries / Valid Deliveries) × 100**

### E. Early/on-time delivery rate

```python
ontime_delivery_rate = len(ontime_deliveries) / len(valid_delivery) * 100
```

Formula:

**Early/On-Time Rate = (Early or On-Time Deliveries / Valid Deliveries) × 100**

### F. Average delay among late orders

```python
average_delivery_delay = late_deliveries['delivery_delay_days'].mean()
```

`mean()` calculates the average.

Here, you are calculating the average delay **only for late deliveries**, not for all deliveries.

### G. Maximum and minimum delay

```python
late_deliveries['delivery_delay_days'].max()
late_deliveries['delivery_delay_days'].min()
```

- `max()` finds the highest delay.
- `min()` finds the smallest delay.

### H. Find the five worst delayed orders

```python
worst_delivery = late_deliveries.nlargest(
    5, "delivery_delay_days"
)
```

`nlargest(5, ...)` returns the five rows with the highest delay.

You then display:

```python
worst_delivery[
    ["order_id", "order_status", "delivery_delay_days"]
]
```

This helps identify the most delayed orders.

# 3. Connect Delivery Performance With Customer Reviews

This is a valuable business analysis because it connects operational performance with customer experience.

### A. Load customer reviews

```python
reviews = pd.read_csv(
    DATA_PATH / "olist_order_reviews_dataset.csv"
)
```

Loads customer review data.

Important columns:

| Column | Meaning |
|---|---|
| `order_id` | Order identifier |
| `review_score` | Customer rating from 1 to 5 |
| `review_comment_message` | Customer's written feedback |

### B. Connect delayed orders with reviews

```python
worst_delivery_reviews = worst_delivery.merge(
    reviews[["order_id", "review_score", "review_comment_message"]],
    on="order_id",
    how="left"
)
```

This is called a **Merge or Join**.

It connects two datasets using their common column: `order_id`.

- `on="order_id"` means match records using order ID.
- `how="left"` keeps every order from the left dataset (`worst_delivery`).
- Review information is added wherever a matching order is found.

This lets you investigate whether the most delayed orders received low customer ratings or negative comments.

# 6. Important Corrections Before Finalising Your Analysis

There are four things to fix:

**1. Remove repeated date conversions.**  
You are converting delivery and estimated dates twice.

**2. Fix your customer satisfaction categories.**  
Use 1–2 dissatisfied, 3 neutral and 4–5 satisfied.

**3. Fix the average rating output.**  
It is a rating out of 5, not a percentage.

**4. Be careful with repeated reviews.**  
Some orders have multiple review records. If you compare delivery delays with customer satisfaction, calculate the average rating per order first. Otherwise, some orders may receive more weight than others.

Also, your current code does not yet calculate the relationship between delivery delay and average customer rating. It only joins reviews to the five worst-delayed orders. That broader comparison is a separate analysis.
